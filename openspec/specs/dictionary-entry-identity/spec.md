# dictionary-entry-identity Specification

## Purpose

为同形词与语法词形提供不依赖拼写、音标或标签的稳定身份，使扩展查询和音标纠错能够按明确证据区分适用条目。保留既有拼写单值查询及旧纠错兼容行为，避免未经确认的迁移将人工修正错误传播到新条目。

## Requirements

### Requirement: 条目身份独立于可变展示内容

系统 SHALL 以稳定条目 ID 区分已建立身份的条目，ID MUST 不依赖 IPA、可变拼写或标签。对身份未发生变化的条目，音标、展示拼写或标签更新 SHALL 不改变其 ID；相同 IPA MUST 不成为合并不同身份条目的理由。

#### Scenario: 条目展示内容变化
- **WHEN** 同一条目的音标、展示拼写或来源标签被更新，但其身份未改变
- **THEN** 该条目的稳定 ID 保持不变，已有身份关联不因展示更新而失效

#### Scenario: 不同条目读法相同
- **WHEN** 两个有明确不同语法身份的条目具有相同 IPA
- **THEN** 系统保留两者的独立 ID，不以 IPA 相同自动合并身份

### Requirement: 拼写查询支持一对多而不合并来源身份

系统 SHALL 在保留旧 ECDICT 拼写单值查询的同时提供独立扩展层，使同一检索拼写能够关联多个条目 ID，并使条目能够按 ID 查询。拼写 SHALL 仅作为检索线索；搜索小写化 MUST 不自动合并不同语言、来源大小写或其他证据所区分的条目身份。

#### Scenario: 同形条目通过扩展层检索
- **WHEN** 一个拼写已关联多个有明确证据的条目
- **THEN** 扩展查询能够取得对应的多个 ID 及各条目信息，而旧拼写单值查询合同仍可使用

#### Scenario: 小写检索命中不同来源身份
- **WHEN** 小写化检索同时命中来源大小写不同或语言不同的条目
- **THEN** 系统保留各自的语言、来源拼写与身份，不仅因为搜索键相同而合并它们

### Requirement: 仅按充分身份证据按需拆分

系统 SHALL 仅在有充分身份证据且需要区分纠错适用条目时按需拆分条目，不强制为整个目标词库重建完整词义或语法体系。多口音与多读法 MUST 不自动产生不同语法条目，来源身份证据不充分时 MUST 不猜测拆分结果。

#### Scenario: 同一身份存在多个口音
- **WHEN** 同一条目获得 UK、US 或多个地域读法，且没有不同语法身份的明确证据
- **THEN** 系统在该条目下保留多读法，不仅因口音或读法数量增加而拆分身份

#### Scenario: 批次缺少拆分证据
- **WHEN** 批次词头的来源无法充分区分词性、词义或词形身份
- **THEN** 系统保留不明身份状态或现有身份，不为追求全词库覆盖而伪造完整语法或义项拆分

### Requirement: read 的四个语法条目具有独立稳定身份与纠错范围

系统 SHALL 为 `read` 建立四个独立稳定条目 ID，分别对应原形（base）、同形普通现在时（present）、过去式（past）与过去分词（past participle），并使四者关联同一动词 lexeme、分别接受音标纠错。系统 MUST 不将 base 与 present 合为同一身份，不因任意两个条目的 IPA 相同而合并身份，也不因旧拼写查询已命中原形或同形词形未进入旧索引而忽略这些扩展身份。该按需拆分 SHALL 不要求为整个词库重建全部语法角色。

#### Scenario: 同形词形同时被查询
- **WHEN** 用户通过扩展查询检索已建立身份的 `read`
- **THEN** 系统返回 base、present、past 与 past participle 四个不同的稳定 ID 及其同一动词 lexeme 关联，原形的旧查询命中不遮蔽其他三个条目，即使部分条目 IPA 相同

#### Scenario: 只纠正原形
- **WHEN** 用户明确将一项音标纠错应用于 `read` base
- **THEN** 该纠错只作用于 base，不自动覆盖同形 present、past 或 past participle，即使 base 与 present 当前显示相同 IPA

#### Scenario: 只纠正普通现在时
- **WHEN** 用户明确将一项音标纠错应用于 `read` present
- **THEN** 该纠错只作用于 present，不自动覆盖 base、past 或 past participle，base 与 present 的独立稳定 ID 保持不变

#### Scenario: 只纠正过去式
- **WHEN** 用户明确将一项音标纠错应用于 `read` 过去式
- **THEN** 该纠错不自动覆盖 base、present 或 past participle，即使过去式与过去分词当前显示相同 IPA

#### Scenario: 只纠正过去分词
- **WHEN** 用户明确将一项音标纠错应用于 `read` past participle
- **THEN** 该纠错不自动覆盖 base、present 或 past，即使过去分词与过去式当前显示相同 IPA

### Requirement: 共享读法须具有对应条目的范围证据

系统 SHALL 仅在证据明确覆盖相应条目的语法 role 时共享读法。仅覆盖 base 的来源 MUST 不自动认证 present 的读法，仅覆盖 past 的来源 MUST 不自动认证 past participle 的读法；拼写相同、IPA 相同或归属于同一 lexeme MUST 不替代适用范围证据。明确覆盖多个 role 的同一来源 SHALL 能供这些独立条目共享，但 MUST 不合并其身份或纠错范围。

#### Scenario: 来源只注明原形
- **WHEN** 来源为 `read` 明确提供 base 读法，却没有支持 present 的适用范围证据
- **THEN** 系统只将该证据用于 base，不将 present 记录为已由该来源认证，即使两者 IPA 相同

#### Scenario: 明确证据支持原形与普通现在时
- **WHEN** 来源明确说明某读法同时适用于 `read` base 与 present
- **THEN** 系统能够让这两个独立身份共享该读法及对应证据，同时保留两个稳定 ID 和各自独立纠错范围

#### Scenario: 来源只注明过去式
- **WHEN** 来源为 `read` 明确提供 past 读法，却没有支持 participle 的适用范围证据
- **THEN** 系统只将该证据用于过去式，不将过去分词记录为已由该来源认证

#### Scenario: 明确证据支持两个词形
- **WHEN** 来源明确说明某读法同时适用于过去式与过去分词
- **THEN** 系统能够让两个独立身份共享该读法及对应证据，同时保留各自独立纠错范围

### Requirement: 未归属旧音标纠错阻断该词新正式结果

系统 SHALL 保留未具有条目范围的旧拼写级音标纠错及其在旧视图中的生效行为，MUST 不将其复制给多个新条目，也不按 IPA 猜测归属。存在未归属旧音标纠错时，系统 SHALL 暂缓该词的新正式音标结果，保留其旧纠错与当前结果，允许生成候选对照且允许其他词继续处理。范围确认 MUST 不被视为发布批准。

#### Scenario: 旧 read 纠错范围不明
- **WHEN** 旧拼写级 `read` 音标纠错尚未确定属于哪个扩展条目
- **THEN** 系统保持旧视图中的纠错与当前正式结果，不复制或猜测迁移该补丁，暂缓该词的新正式结果，并可继续提供候选对照及处理其他词

#### Scenario: 用户只确认纠错范围
- **WHEN** 用户确认旧纠错属于某个条目，但尚未明确批准新候选批次发布
- **THEN** 系统记录纠错归属，但不将范围确认当作发布许可，也不因此发布该词新正式结果

### Requirement: 公共旧查询与逐字段纠错保持兼容

系统 SHALL 保持公共旧查询、拼写级纠错提交与既有 v1 纠错数据可用，保留 `word`、`meaning`、`phonetic` 字段的既有语义及逐字段优先行为。系统 MUST 不机械地将所有旧拼写参数改为 ID，不把扩展结果任意第一项当作旧单值结果，不忽略已有拼写或释义纠错，也不将旧拼写级字段未经范围确认传播给多个新身份。

#### Scenario: 旧纠错数据包含多个字段
- **WHEN** 旧 v1 数据或公共旧纠错提交同时包含展示拼写、释义和音标字段
- **THEN** 旧查询与纠错视图继续按原字段语义使用这些数据，新增音标能力不丢弃 `word` 或 `meaning`，也不将其随意复制到多个扩展身份

#### Scenario: 扩展条目顺序变化
- **WHEN** 某词的多个扩展条目返回顺序发生变化
- **THEN** 旧单值查询不因随意选择新的第一项而改变结果归属，旧公共调用不被强制改为 ID 调用
