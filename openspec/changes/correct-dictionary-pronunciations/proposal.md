# Proposal

## Why

当前 ECDICT 查询以拼写映射单一音标字段，现有拼写级纠错无法区分同形语法条目，也缺少新增音标的来源追溯与多读法管理。需要在保留原始数据和已有纠错的前提下，建立可分批、可审批、可归因的 IPA 显示修正机制（不涉及声音）。

2026-10-18 需求扩展：用户要求首轮 100 词及以后批次最终落实为产品中的正确 IPA，而非停在候选清单。本轮继续 `correct-dictionary-pronunciations`，因为落库、版本审批和长期轮换正属本 change 第 11–12 组；另开 change 会形成两套发布合同。唯一权威迁移方向已获用户确认（评论 `01a14e5a-0cd6-7e9e-b259-02e1a80f8fdb`），本轮合入规划并离线修复采集器；第 13 组实施、正式发布和长期预算仍未执行，不能由方向同意推导操作授权。

## What Changes

本变更引入以 Wiktionary 官方按词接口为主来源的独立音标纠错层，新增衍生音标按 CC BY-SA 4.0 管理；**本次不实现任何代码**，仅确立以下将要实现的行为范围：

- 先核验已冻结的 100 词，将其中证据充分且获准的修正写入系统纠错层并交付可验证构建；范围不明或无证据的词明确列为阻塞，不承诺 100 词必有 100 条纠正。后续评估未核验 3,786（其中 ASCII 简写嫌疑 2,386）及遗留记法 33,962 的去重分批路径；约 46,803 仅为目标库盘点基线，不承诺本轮或一次性全库治理。**不修改 ECDICT 原始数据与元数据，不顺带覆盖释义**；音标作为独立许可的隔离数据，附带源 URL、history 归因、license 链接、变更标记与同许可声明。不抓取商业词典（默认无再分发权），不宣称整个应用代码必须采用 CC（Wiktextract 代码 MIT ≠ 数据 MIT）。
- 采用唯一、带范围和证据的系统音标纠错记录作为权威；旧 `dictionarySystemCorrections.json` 的音标部分成为兼容投影，overlay 系统规则和发布快照从同一版本派生。该迁移解决旧 JSON 无法表达 `read` 四角色的问题；不另建可独立编辑的第二套权威。保留用户纠错优先级、旧三条勘误及 word/meaning 字段；版本不一致阻断发布。
- 新增修正逐条记录外部依据、范围、核验人与时间、许可及批准引用。Wiktionary 衍生数据必须附 CC BY-SA 4.0 署名、history、许可和变更说明；现有三条历史引用保留但不据此推定商业来源再分发权。审计 `verifiedErrors` 由同一核验记录派生，不再独立维护新增纠正值；区分已核验、已批准与已发布。
- 建立**三层数据模型**：独立来源读法层 → 修正规则层 → 最终生效结果层。保存全部读法及其原始标签、适用范围与来源证据；对 pos/词义/词形不明确的来源**不猜测**。
- 定义**优先级规则**：在可比较且明确的适用范围内，用户纠错 > 系统勘误 > 合格新来源 > 旧 ECDICT；新合格值即使旧值无显错也可优先；**不得整词替换而误删尚未覆盖的旧读法**；旧值留作追溯，不确定值须标注；采集失败/缺页/来源暂缺**不能**清空现结果或被当作"错误"证据。旧式 IPA 记号不一律判错。
- 定义**复核时效**：人工与系统纠错默认自创建或最近一次明确核验起 **6 个月**复核，到期保留优先以待复核；上游 IPA / 口音 / 条件变化可提前触发；采集成功**不**刷新人工核验时间；撤销/替代须经确认。
- 定义**口音与变体表示**：完整合格的无口音 IPA 可作默认但须明确标注为"未注明口音"，不伪装 UK/US、不当作通用双音齐全。通用/标准（RP、SSB、GA）、未进一步限定地域的 UK/US 优先；地域性读法全部保存并保留地域标签作为补充，只有地域读法时也可带标签展示，但不冒充通用读法。rare 可参与默认并留标签，仍受地域规则约束；archaic/obsolete 只作补充。同口音且适用条件明确对应时 phonemic 优先、phonetic 补充；只有完整合格 phonetic 时可参与默认并保 `[]`，类型不明不猜；片段仅留证据不充作完整读法。（精确标签表与门槛待 design 确定。）
- 定义**官方按词采集**：使用 Wiktionary Action API 按词展开 English 段为主，**不下载处理全量 dump**，不依赖 Kaikki postprocessed 下载入口（上游已宣布移除相关链接，端点长期可用性未获保证），Kaikki 仅可选对照。**首轮预算上限**：最多 100 词头（缺页/失败均计入）/ 20 MiB（所有辅助与重试响应体解压后累计），任一上限即暂停且不自动扩大；触限即中止读取，不把截断视为有效数据；串行、低速、合规 UA、失败退避，需支持断点恢复；实际网络量另计。月度限额任务推进初次分批覆盖并在覆盖后轮换复查，**只生成候选差异**，不是每月全库抓取；长期预算待首轮量测后再定，不得自动套用 100 词/20 MiB。页面 revision 不能单独反映模板/模块依赖变化，因此需周期性重渲染并保存提取时间、规则版本与相关内容指纹作为来源证据。**尚未量测全库流量、准确率、覆盖率，不作保证。**
- 定义**候选报告与审批**：首轮候选报告列出受影响词，突出替代/排除/范围不明及对应依据，经用户**明确批次批准**后才发布，可排除部分词；后续发布不自动沿用既有授权；未批准不改正式结果。已确认批准须绑定固定候选版本的具体内容、发布纳入/排除词头名单与当前正式基线；候选内容、适用 scope、纠错归属、名单或正式 baseline 实质变化时，须重新生成差异并重新批准，旧批准不得用于变化后的发布。只有报告排版改变、上述实质内容不变时不要求重新批准。具体操作 UI 与流程呈现仍待确定。
- 定义**拼写与身份**：拼写仅用于检索，条目稳定 ID 不依赖 IPA、可变拼写或标签；保留旧 ECDICT `Map`，另建独立扩展层 `spelling → ids` 与 `byId`。仅在有充分身份证据时**按需**拆分条目，不做全词库语法重建；多口音/多读法不自动拆语法条目。已确认 `read` 在本变更中建立 **4 个独立稳定 ID**：原形（base）、同形普通现在时（present）、过去式（past）、过去分词（past participle），关联同一动词 lexeme，四者均可分别纠错；原形与 present 不合一，IPA 相同不合并身份。共享来源仅限证据明确覆盖的 role，base 来源不自动认证 present，past 来源不自动认证 past participle。此决定不扩展为全库全 grammar 重建。完整 lexeme/sense 拆分、ID 格式、合并拆分继承细则、接口与展示由 design 细化，具体操作 UI 尚未确定。
- 定义**旧纠错兼容**：现有旧 word 纠错无条目范围，不复制为多条、不按 IPA 猜测；旧音标纠错若未归属则**暂缓该词的新正式结果**，保留旧纠错与当前结果，候选可作对照，其余词继续。范围确认与发布批准是两件事。公共旧查询/纠错保持兼容，不将新结果任意作为第一项、不机械地把 `word` 全换为 ID。

## Capabilities

### New Capabilities

- `dictionary-pronunciation-overlay`：独立来源读法层、修正规则层与最终生效结果层的叠加模型，含来源/许可隔离、保存全部读法与标签、按适用范围的优先级、旧值追溯与不确定标注；新增系统纠错唯一权威、旧 JSON 兼容投影、overlay 同版本发布与一致回滚；显示为 IPA 而非声音。
- `dictionary-entry-identity`：拼写仅作检索，稳定条目 ID 与拼写/IPA/标签解耦；旧 `Map` 保留并新增 `spelling → ids` / `byId` 扩展层；按证据需求拆分语法条目并支持旧纠错兼容。
- `dictionary-pronunciation-refresh`：官方按词 Action API 采集，首轮预算（100 词头 / 20 MiB 解压后累计）与可暂停可恢复；月度预算轮换、候选差异报告、差异审批与来源归因；新增落库批准者身份绑定、审计核验记录衔接、首轮交付计数及分批常态流程；复核时效与触发条件。

> 以上能力已在本 change 的 spec 中形成未来行为契约；当前授权允许完善 proposal、spec、design 与 tasks 等规划文件，**不构成实施、采集或发布授权**，不表示任何运行时代码已实现或就绪。

### Modified Capabilities

无（项目当前 `openspec list --specs` 返回 No specs found，尚无既有 capability 的规格行为需要修改）。

## Impact

- **本轮文档增量**：扩展现有 proposal、overlay/refresh 两份 delta spec、design 与 tasks；identity spec 保持原合同。此前实施证据及勾选不证明新增落库链已实现。
- **未来系统纠错迁移**：计划新增 `src/data/dictionarySystemPronunciationRules.json` 权威记录及独立归因资产，由其生成旧 JSON 音标投影并适配 `src/pronunciation-overlay/` 与 `scripts/pronunciation_publication.mjs`。`src/data/SYSTEM_CORRECTIONS.md` 的直接手编音标流程须同步更新；审计脚本和现有 corrections/audit 测试需验证同源与许可，不能只增加硬编码预期条数。

- **来源数据**：新增 Wiktionary 衍生音标按 CC BY-SA 4.0 管理，与 ECDICT 原始数据隔离，附具体源条目 URL（可访问作者历史）、license 链接、变更标记与同许可声明；可选对照数据仍须核查来源及许可，不将提取工具的 MIT 当作数据许可。
- **增量工具**：按 design 新建独立 Python 按词采集/重渲染/差异比对工具，记录规则版本与内容指纹；现有 `scripts/generate_wiktionary_phonetics.py` 的巨型 dump 主流程及产物保持不变，不作为新流程依赖。
- **查询与纠错接口兼容**：`src/englishChineseVocabularyPack.ts`（Map 拼写单值）、`src/lookupEnglishChinese.ts`（直接查 single，命中后不查同形反变形）、`src/dictionaryCorrections.ts` 与 `src/useDictionaryCorrections.ts`（拼写级 `Record`、`localStorage` v1、公共 `onChange(word, patch)`）、`src/englishInflectionPack.ts`（已数组索引）与 `scripts/generate_ecdict_inflections.py`（过滤 `form == word`）；扩展层并非默认必须改动原生成器。兼容需保持现有公共查询/纠错可用。
- **显示与证据归因**：`src/formatDictionaryPhonetic.ts` 当前"非中文全部英标签"为需关注的显示问题；本次仅记录该问题，UI 具体方案不在此定。
- **测试**：预计影响音标来源核对、优先级与保留判定、审批阻断、read 同形不覆盖、预算启停恢复、来源可追溯等测试范围。
- **语音与学习进度**：本次不修语音（`src/kokoro.ts` 及 worker 与音标显示目前相互独立），项目没有学习系统，故不构造学习进度迁移。
- 不硬性标记 **BREAKING**：design 已规定保留旧接口与 v1 数据、以 opt-in 扩展和受核验投影共存；兼容性仍须在实施阶段通过回归验证。

## Non-goals

- 当前仅完善 proposal、spec、design 与 tasks 等规划文件，不修改实现代码；规划文件授权及上述设计确认均不构成实施、真实采集或正式发布授权。
- 不修改 ECDICT 原始数据、元数据或释义，不顺带覆盖释义。
- 不生成/播放声音，不实现 TTS 变更。
- 不做学习系统或学习进度迁移。
- 不下载处理巨型全量数据集，不在单次或每月任务中强制抓完整词库；不排除经限额批次逐步覆盖整个目标词库。
- 不抓取商业词典、不采集无再分发权素材。
- 不把"整个应用代码必须 CC 许可"作为结论。
